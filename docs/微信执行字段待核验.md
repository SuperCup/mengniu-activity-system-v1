## 实施时必须核验的条件

| 字段/条件 | 已有证据 | 后续处理 |
| --- | --- | --- |
| 名称长度与字符集 | 后台基础页提示9个字；API另区分中文与字母长度 | 按入口核验混合字符计算方法；保留正式规则来源 |
| 有效期上限 | 后台代金券手册365天，普通商户API90天；立减手册为3个月 | 按产品/入口分别处理；3个月不能简单写成90天 |
| 每人限领/参与 | 代金券API为1—60且不得超总数；立减为参与次数 | 核验当前后台范围，不能统一写100，也不能把次数写成领券张数 |
| 营销经费与资金承担 | 基础页区分预充值/免充值，另有出资方、扣款方式等概念 | 建模分开；按账号能力确认条件必填与授权关系 |
| 归属商户与核销商户 | 后台手册与API对归属商户支持范围不同 | 分开记录，核验实际创建账号类型与可选商户关系 |
| 总数量、总预算、每日限额 | 代金券API有数量、总金额及每日金额限制；后台还有每日张数概念 | 不混用金额与数量；确认后台字段单位、必填标志及计算公式 |
| 固定优惠、随机优惠、折扣 | 浏览器可见定额/随机；官方手册包含随机分档与全场折扣 | 核验各分支表单、单笔封顶、预算和重复参与控制 |
| 领取后有效、生效及特殊时段 | 后台手册描述多种规则；部分API字段标注暂未开放 | 按当前入口和账号能力启用，不能默认API全部支持 |
| 展示说明、品牌素材、跳转 | 后台与API字数及品牌能力条件不同 | 核验必填标记、长度、商户/品牌/AppID关系，不统一写100字 |
| 单品活动 | 已确认存在独立入口；当前未查看具体字段 | 进一步查单品规则及支付下单上送明细前提；不可按全场表单宣称配置完整 |

待核验条件影响执行时，应允许保存本地草稿，明确显示条件尚未确认并阻止“配置就绪”。不影响的其他功能继续实现。完成核验后补充页面/文档章节、账号类型、入口、日期及结论。

本系统可自行要求业务人员明确填写某些内容，但必须标为“业务要求”，不能因此声称它是“微信平台必填”。


## 本轮实现中的落地位置（2026-10-21）

| 条件 | 界面标记 | 是否阻断「配置完成」 | 是否阻断「推送服务商」 |
| --- | --- | --- | --- |
| 批次/活动名称长度、字符集 | 仅提示，不做硬校验 | 否 | 否 |
| 有效期上限（365 / 90 天 / 3 个月） | 不限制跨度，只校验开始≤结束 | 否 | 否 |
| 每人限领 / 参与次数 | 必填，只校验正整数 | 是（未填时） | 是（通过配置状态） |
| 营销经费模式（预充值 / 免充值） | 必填下拉 | 是 | 是 |
| 归属商户号与核销商户号 | 归属商户号必填（代金券）；核销商户号来自门店明细 | 是（代金券） | 是 |
| 商户授权核验 | 必填下拉：待核验 / 已核验 / 不适用 | 是 | 是 |
| 微信创建条件（授权、待核验字段） | 配置抽屉底部单独一行 | 否 | 否 |
| 数量 / 预算 / 每日限额 | 数量必填整数；单日不超过总数量 | 是 | 是 |
| 折扣比例与封顶 | 折扣填 8.5 表示支付 85%，配单笔封顶 | 是 | 是 |
| 展示说明、品牌素材 | 使用须知必填（本系统业务要求），品牌可选 | 是 | 是 |
| 单品活动 | 未开放，商品限制仅记录范围 | — | — |

说明：

1. 「配置完成」只校验上面标为阻断的项，均为本系统业务要求或已核验的确定性规则；
   不套用「门槛必须大于面额」「有效期 90 天」「每人 100 张」「说明 100 字」等未核验的通用规则。
2. 未核验项集中显示在配置抽屉的「微信创建条件：待核验 N 项」，页面不会出现「已具备微信创建条件」。
3. 推送服务商只要求计划配置完成，不要求微信侧核验通过；外部创建与激活仍由服务商在商户后台人工完成并回填。
