基本信息 · 预算与费用科目 · 服务商 · 计划与批次明细。

保存草稿保持「草稿」；提交后生成 16 位项目编号，进入「审批中」。

02 · 审批节点

BPM 并联审批

BPM 接收审批单

系统只提交审批单，不建设审批引擎，不提供通过 / 驳回 / 撤回按钮。

审批人 N 人并联

审批人之间无先后、无分级；可多选，按项目分别授权。

全部同意 → 已通过

所选审批人全部同意，回写「已通过」，项目进入待推送。

已通过

任一未通过 → 未通过

任一人未通过即回写「未通过」，项目退回创建人修改。

未通过

按人回写结果

返回每位审批人的结果、处理时间与审批意见，项目详情时间轴按人展示并汇总已同意人数。

→
已通过
03 · 推送节点

批次配置与推送

已通过 / 待推送

补齐批次配置：券名称、面额 / 门槛、可用时间、发放上限、使用说明、券图、零售商与商品。

待推送

配置校验

商户号在小程序「可发券商户号」清单内；批次号由服务商后续回传，创建人只读。

推送确认

确认已与名单内零售商达成合作、已通知回传；确认后推送服务商并发送专属链接。

已推送 / 服务商确认

服务商打开专属链接确认承接；项目进入「待确认 → 已确认」。

已推送待确认已确认

推送后锁定

计划批次、机制类型、机制详细字段与批次配置全部只读；计划行仅保留「明细」。

→
确认承接
回传批次
04 · 执行节点

执行与结束

服务商回传

在微信商户平台建券后，回传批次号与微信商户号；平台校验归属与白名单。

已配置

批次号回传并校验通过，等待账单与核销数据。

已配置

执行中

批次计划生效，消费者领券 / 核销；服务商按周期回传账单。

执行中

已结束

项目周期自然结束；或业务调整提前终止，释放预算额度、保留历史数据。

已结束

终止 / 异常

仅无批次推送等允许条件可终止；已推送批次不可直接终止，需先处理批次。

关键规则

审批

并联、无先后；全部同意才通过，任一未通过即未通过。

批次

推送后只读；仅「已通过 / 待推送」可补配置。

门店编码

客户系统原值，格式不限；只校验必填与重复。

挂券

单小程序；商户号白名单；服务商回传批次号 / 商户号。

边界：系统不建设 BPM 审批引擎，不代替微信商户平台建券；审批动作在 BPM 完成，平台只提交审批单并接收结果。批次配置在推送后锁定，服务商通过专属链接完成确认、下载与回传。
