- 日期：2026-10-30
- 依据：当前原型页面实际可见、可点击、可校验的功能，不以“有没有对应文件”作为判断依据。
- 用途：作为 PRD 增补/修改的范围基线，供产品、研发、测试对齐；不是完整 PRD 全文。
- 本次同步：项目列表去掉节点统计条，改为按节点分组的状态筛选；项目详情改为 4 节点时间轴并展开审批人结果/意见；推送后批次配置只读；返回入口统一到主内容区左上角。

## 一、范围结论

### 1.1 本期纳入（P0）

1. 总部端项目全生命周期：草稿 → 审批中 → 已通过 → 待推送 → 已推送 → 待确认 → 已确认 → 已配置 → 执行中 → 已结束；审批未通过可编辑后重新提交。
2. 项目创建、计划与批次、批次完善配置。
3. 活动零售商、活动商品明细及导入模板。
4. 挂券与配置：单小程序、可发券商户号、发券任务/推送批次。
5. 推送服务商前确认。
6. 服务商操作页：批次计划工作簿、券图下载、批次回传。
7. 角色与数据可见范围、系统日志、门店与商户号、商品维护。
8. 全局口径：16 位项目编号、门店编码保留客户系统原值、菜单命名、去版本号。

### 1.2 明确不纳入本期（P1/后续）

| 项 | 现状 | 处理建议 |
|---|---|---|
| 计划变更（v1.1） | 已从原型移除菜单、页面、路由与相关代码，不再可见或可操作 | 不在本期；PRD 单列二期，不从旧代码恢复 |
| 多小程序 | 当前仅“蒙牛会员服务中心”一个 | 后续扩展时再做渠道池 |
| 多投放平台 | 仅微信支付 | 其他平台不设计 |
| 真实邮件发送 | 原型仅记录“已发送”，不接邮件服务 | 研发接邮件网关，PRD 补模板/重试/退信 |
| BPM 审批引擎 | 审批在 BPM 完成；系统只提交审批单、接收审批结果 | 不重复建设审批流，不提供任何审批动作 |
| 预算系统校验 | 预算单号/额度为原型模拟 | 接 TPM/MEM/财务预算接口后替换 |
| 微信支付后台建券 | 服务商线下在商户平台操作 | 不接微信建券 API |
| 数据看板取数 | 原型为演示数据 | T+1 数据链路单独立项 |
| 图片持久化 | 券图仅当前会话内存，刷新后需重新上传 | 生产必须接对象存储并落库 |

## 二、角色与权限

| 角色 | 能看到的菜单 | 数据范围 | 说明 |
|---|---|---|---|
| 管理员 | 全部菜单 | 全部项目 | 可维护角色、组织、服务商、字典 |
| 业务运营 | 除系统管理外 | 自己创建、担任负责人、作为审批人的项目 | 可创建项目、配置批次 |
| 审批人 | 不单独设角色 | 作为审批人的项目 | 审批动作在 BPM 完成，系统只提交审批、回写结果 |
| 服务商 | 无系统账号 | 仅邮件链接对应的单个活动 | 免登录，链接与项目编号绑定、有有效期 |

PRD 要点：
- 删除财务角色、服务商角色；服务商不是系统用户。
- 删除“数据范围”配置项，数据范围固定为“创建人 / 负责人 / 审批人”。
- 原型的前端过滤只是演示，正式权限必须由后端接口强制。

## 三、项目状态机与修改规则

### 3.1 四节点、十一状态

| 节点 | 状态 |
|---|---|
| 草稿 | 草稿 |
| 审批 | 审批中、已通过、未通过 |
| 推送 | 待推送、已推送、待确认、已确认 |
| 执行 | 已配置、执行中、已结束 |

- 项目列表不再单独展示节点统计条；筛选条提供状态下拉，按 4 个节点分组列出 11 个状态及各自数量。
- 项目详情不再单独放「项目过程」状态区；当前状态在标题后标签展示，底部用 4 个节点的时间轴展示状态流转。未到达的节点显示「未开始」，不提前显示待推送 / 执行中。审批节点展开显示每位审批人的结果、已处理时间和审批意见，并汇总已同意人数。
- BPM 回写除最终审批结果外，还需提供每位审批人的结果（通过 / 未通过 / 审批中）、处理时间和审批意见，供项目详情时间轴按人展示。
- 项目卡片进度条显示 4 个节点；当前节点显示当前状态，已走过节点显示该节点最终状态（如 审批→已通过、推送→已确认、执行→已配置 / 执行中 / 已结束）。
- 审批在 BPM 完成；系统只负责提交审批单、接收审批结果，不在系统内做通过/驳回/撤回等任何审批按钮。
- 审批人可多选，审批人之间没有先后、没有分级，为并联审批：所选审批人全部同意才回写“已通过”，任一人未通过则回写“未通过”。界面不出现“第几级 / 当前审批人”等顺序概念。
- 项目编号 16 位：年月日 8 位 + 8 位数字，提交审批后生成；全站统一展示该编号，不再展示内部 ID。

### 3.2 信息修改规则（必须写进 PRD）

| 阶段 | 计划批次 | 机制类型/活动周期 | 机制详细字段 |
|---|---|---|---|
| 草稿 | 可增删改 | 可改 | 可改 |
| 审批中 | 锁定，不提供编辑入口 | 锁定 | 锁定 |
| 已通过 / 待推送 | 不能增减计划批次 | 不能改 | 可补面额、门槛、发放上限等 |
| 已推送及之后 | 不能增减 | 不能改 | 全部锁定，仅查看 |

- 批次一旦推送服务商，批次配置只读；计划行和计划详情不再出现「补充配置」；待完善的计划行显示「已锁定」，其余只保留「明细」。
- 计划变更（新增批次/增删门店商品）属于 v1.1，不在本期。

## 四、项目创建

### 4.1 页面字段

1. 基本信息：项目名称、项目目标、投放平台（仅微信支付）、活动周期、活动负责人、联系方式。
2. 预算与费用科目：预算系统（TPM / MEM / 其他）、预算凭证、预算单号（已校验）、核销预算、费用科目、承担主体、预算来源。
3. 服务商信息：服务商、对接联系人、邮箱。
4. 审批与协作：项目审批人（必填、可多选；审批人之间并联、无先后分级）；系统只提交 BPM 审批并接收结果。
5. 批次计划：机制、活动零售商、活动商品；提交时生成 16 位项目编号。
6. 底部动作：项目节点与状态（只读说明）、保存草稿、提交审批。

### 4.2 活动零售商（本轮新增/调整）

必填：
- 门店编码（必填，来自客户系统；当前不限定格式，仅去除首尾空格，不自动补齐或生成；同一次提交内不可重复，主数据编码全平台唯一）
- 零售商名称
- 省份
- 城市

选填/规则：
- 门店名称：选填。
- 微信商户号：选填；填写时必须为 8~10 位阿拉伯数字；不合规弹二次确认，确认后允许保存。
- 经度、纬度：选填，保留小数文本。
- “—”占位按空值处理，不能绕过必填校验。
- 导入模板列：门店编码、零售商名称、门店名称、省份、城市、微信商户号、经度、纬度。

### 4.3 活动商品

- 必填：69 码或店内码、商品名称、店内码所属零售商。
- 69 码、店内码在提交时去重；重复直接拦截。
- 数量上限：满减 ≤ 15000 个/批次，减至（换购）≤ 5000 个/批次。

## 五、计划与批次 / 批次完善配置

### 5.1 计划列表

- 列：计划 ID、所属项目（显示 16 位项目编号）、计划名称、机制、发放数量、计划金额、有效期、批次号、计划状态、操作。
- 状态筛选：待完善、待配置、进行中、已结束、已中止。
- 「补充配置」仅在计划待完善且项目处于「已通过 / 待推送」时显示；项目推送后入口关闭，只保留「明细」。
- 计划明细抽屉展示与批次配置一致的字段。

### 5.2 批次必填字段

| 字段 | 规则 |
|---|---|
| 券名称 | 必填，≤ 9 个汉字；超长微信商户平台直接拒绝 |
| 批次号 | 由服务商在微信支付后台建券后回传；6~20 位数字且全局唯一 |
| 机制类型 | 满减 / 减至（换购） |
| 券面额 / 减至价 | 按机制填写；减至对应微信支付换购券 |
| 使用门槛 | 满减必填 |
| 可用时间 | 必须落在项目活动周期内；时间跨度 ≤ 90 天；支持“有效期内任意时间可用”或“领券后 N 天可用” |
| 发放总上限 | 必填，6 张及以上整数；草稿保存也按此校验 |
| 单人可领个数 | 必填，≥1 且 ≤ 发放总上限 |
| 使用说明 | 必填，≤1024 字，消费者可见 |
| 券详情图 | 选填 1 张；JPG/PNG；尺寸 ≥537×202（建议同比例 2x/3x）；≤5MB |

### 5.3 活动零售商

- 必填：门店编码、零售商名称、省份、城市；门店名称选填。
- 门店编码保留客户系统原值，不按 MD + 6 位等固定格式校验；导入、批次保存只校验必填与重复。
- 微信商户号：选填；8~10 位数字；不合规二次确认；且必须在当前小程序「可发券商户号」清单内。
- 经度、纬度：两列可编辑，明细只读展示。
- 批次明细与配置页字段一一对应。

### 5.4 活动商品

- 必填：69 码、商品名称、店内码、所属零售商。
- 同批次内 69 码或店内码任一重复即拦截。
- 数量上限：满减 15000、减至 5000。

### 5.5 券详情图

- 上传后显示预览、文件名、更换/移除。
- 保存后计划上记录文件名与上传时间；批次明细显示缩略图。
- 服务商操作页可“下载券图”：按计划 ID 命名（PL-01.png / .jpg），多张打包 ZIP。
- 原型限制：图片文件只在当前会话内存中，刷新后需重新上传；生产必须落对象存储。

### 5.6 保存校验顺序（建议写进 PRD）

1. 基础字段：券名称、时间、面额/门槛、上限、单人、说明。
2. 零售商：必填四项、门店编码重复校验、商户号格式（软确认）、商户号白名单。
3. 商品：数量上限、69 码/店内码去重。
4. 已推送/审批通过的项目先做锁定校验，不进入编辑。

## 六、挂券与配置

- 仅一个小程序：蒙牛会员服务中心（AppID wx8f3a2c9d1e4b6a70）。

- 发券任务展示任务号、项目、批次、推送时间、状态。

## 七、推送服务商

- 触发条件：项目状态为「待推送」，批次配置已完成。
- 推送前必须弹确认抽屉，正文固定：
  > 请确认：与本项目配置名单中的零售商已达成合作，且已通知零售商打开单品回传操作。避免因名单信息错漏，或合作尚未达成、后续中止等原因产生消费者客诉，或其他数据披露风险。
- 按钮：暂不推送 / 确认推送；取消不改变状态。
- 确认后写入：推送时间、推送人、计划清单，记录日志，并模拟发送邮件。
- 推送后计划批次、机制类型、机制详细字段均锁定，批次配置入口关闭。

## 八、服务商操作页

### 8.1 访问方式

- 服务商无账号，通过邮件专属链接进入；链接与项目编号绑定、有有效期，活动终止即回收。
- 页面只展示当前活动，不暴露 BU / 部门预算总额与内部审批意见；活动核销预算仅用于服务商配券。

### 8.2 下载批次计划（工作簿）

5 个 Sheet：

1. 批次计划
2. 活动零售商
3. 活动商品
4. 可发券商户号
5. 填写说明

本轮明确：

- 「批次计划」不包含“批次状态”列。
- 「可发券商户号」只保留一列“微信商户号”，按清单逐行罗列，不出现序号、小程序名、AppID。
- 「批次计划」列：投放平台、计划 ID、计划预算、机制、券名称、批次号（留空待回传）、机制类型、券面额、减至价、优惠门槛方式、使用门槛/订单金额、商品最高单价、可用开始时间、可用结束时间、可用时间方式、领券后可用天数、发放总上限、单人可领个数、使用说明。
- 「活动零售商」列：计划 ID、门店编码、零售商名称、门店名称、省份、城市、微信商户号、经度、纬度。
- 「活动商品」列：计划 ID、69 码、商品名称、店内码、店内码所属零售商。

### 8.3 下载券图

- 按计划 ID 命名，多张打包 ZIP；无图时提示。
- 只打包当前会话有文件的计划；刷新后需重新上传。

### 8.4 批次回传

- 模板列：项目编号、计划 ID、计划编号、计划名称、券名称、批次号、微信商户号。
- 批次号：必填，6~20 位数字，全局唯一。
- 微信商户号：必填，8~10 位数字，且已登记在门店库、并在「可发券商户号」清单内。
- 回传后更新计划批次号、商户号、批次状态。

1. 菜单：「挂券与配置」「服务商操作页」「门店与商户号」「商品维护」命名统一。

| R-07 | 商户号池 | 小程序维护可发券商户号；推送后锁定；批次/回传双校验 |
| R-08 | 推送确认 | 固定确认文案；暂不推送/确认推送；确认后才变更状态 |
| R-09 | 服务商工作簿 | 5 个 Sheet；批次计划不含批次状态；商户号 Sheet 仅一列 |
| R-10 | 主数据 | 门店与商户号增加经纬度展示；导入模板同步 |
| R-11 | 全局 | 16 位项目编号、门店编码保留原值、菜单/文案统一、去版本号 |

## 十二、遗留问题与需产品确认

1. 计划变更页：已从原型删除菜单、页面与代码，原“是否隐藏菜单”的问题关闭；如启动二期，重新按独立需求设计。
2. 券图持久化：生产是否接对象存储？刷新后重新上传不可接受，PRD 需明确存储、大小、审核与删除策略。
3. 商户号清单维护权：总部维护还是小程序方提供？推送后锁定的时点是否以“首个批次推送”为准？
4. 15000 / 5000：是微信支付平台硬限制还是业务限制？超限拦截文案与导入失败提示需明确。
5. 经纬度：选填还是必填？来源是门店库带出还是手工填写？
6. 商户号 8~10 位软校验：二次确认后仍保存，是否需要记录“已确认风险”日志？
7. 服务商回传批次号唯一性：跨项目全局唯一还是项目内唯一？原型按全局校验。
8. 数据看板：演示数据与正式取数口径需另附指标字典。

## 十三、验收基线（按可见功能）

- 11 个页面可正常打开，0 console 报错。
- 项目列表：不再出现节点统计条；状态下拉按 4 个节点分组，选择状态后列表与数量联动。
- 项目详情：状态流转为 4 节点时间轴；未到达节点显示「未开始」，不提前显示待推送 / 执行中；审批节点显示已处理审批人的结果、时间与意见，并汇总已同意人数。
- 推送后的项目：计划与批次页不出现「补充配置」，仅保留「明细」；直接打开配置入口被拦截。
- 项目详情、计划与批次、补充配置页的返回按钮位于内容区左上角，底部操作栏不再放返回按钮。
- 创建页：基本信息 / 预算 / 服务商 / 项目审批人 / 批次计划五段完整；项目审批人必填；底部有「项目节点与状态 / 保存草稿 / 提交审批」；零售商缺省省份/城市时无法完成；商户号 123456 触发二次确认；导入模板 8 列。
- 批次配置：券名称 10 字、说明 1025 字、上限 5、单人 0、单人>上限、商品重复均被拦截；券图 400×150 被拦截，1074×404 通过。
- 门店编码：任意非空文本（如 `CQ001`、`SZ-HL-01`）均可保存；缺编码被拦截，重复编码被拦截，不再提示 MD + 6 位格式。
- 小程序详情：可发券商户号可见；有推送批次时显示锁定，不能增删。
- 推送：弹窗文案与按钮正确；暂不推送状态不变；确认推送后状态变更并记日志。
- 服务商：下载工作簿 5 个 Sheet；批次计划无“批次状态”；商户号 Sheet 仅“微信商户号”一列；券图 ZIP 文件名=计划 ID。
- 门店与商户号、批次明细可见经纬度。
